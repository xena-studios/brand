# Building

Every asset is generated by [`scripts/build.ts`](../scripts/build.ts). Needs Node 24 and pnpm.

```sh
pnpm install
pnpm build       # regenerate every asset
pnpm check       # rebuild, and fail if anything committed is out of date
pnpm typecheck   # type-check the scripts
pnpm verify      # no fonts needed: type check, every SVG renders and has a PNG, tokens parse, docs links work
```

## Fonts

The build outlines every letter, so no font ever ships, but it needs the fonts to do that. Put them in `.local-fonts/`, which git ignores:

| File | Where to get it |
|---|---|
| `Ethnocentric-Regular.otf` | Your own licensed copy from Typodermic |
| `HankenGrotesk-700.ttf` | Google Fonts (static instance) |
| `SpaceGrotesk-700.ttf` | [floriankarsten/space-grotesk](https://github.com/floriankarsten/space-grotesk), `fonts/ttf/static` |
| `Geist-700.ttf`, `GeistMono-500.ttf` | [vercel/geist-font](https://github.com/vercel/geist-font) |
| `LilitaOne-400.ttf` | [google/fonts](https://github.com/google/fonts), `ofl/lilitaone` |

JetBrains Mono (Regular, Light and SemiBold) is read from `~/Library/Fonts`.

To use a font from somewhere else, set its path with one of these: `ETHNOCENTRIC`, `MONO`, `MONO_LIGHT`, `MONO_SEMIBOLD`, `HANKEN_BOLD`, `GROTESK_BOLD`, `GEIST_BOLD`, `GEIST_MONO`, `LILITA`.

## How the build works

- Running the build twice changes nothing. Each SVG's ids start with its own path, so a file only changes when its graphic does.
- Commit the generated files with the change that produced them.
- The scripts are TypeScript that Node runs directly, so there's no compile step. Stick to syntax Node can strip (no enums, namespaces or parameter properties). `tsconfig.json` enforces this.

## CI

CI can't run the build because Ethnocentric can't be in the repo, so **run `pnpm check` before opening a pull request**. CI runs `pnpm verify` ([`check.yml`](../.github/workflows/check.yml)), which `main` requires, and CodeQL ([`codeql.yml`](../.github/workflows/codeql.yml)).

## Files that aren't generated
